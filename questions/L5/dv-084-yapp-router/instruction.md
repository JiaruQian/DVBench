# dv-084-yapp-router: Build a Complete UVM Verification Environment

Read `public/spec.md`, `public/ports.md`, `public/submission_format.md`, and `submission_contract.json`, together with `public/debug_feedback.md`. The native DUT top is `yapp_router`. Instantiate exactly one complete parameterless `yapp_router`, with neither `INT_SUPPORT` nor `INJECT_ERROR` defined. The RTL implementation is hidden.

Submit `flow/features.md`, `flow/features.json`, `flow/testplan.md`, `flow/testplan.json`, a self-contained `model/model.sv`, complete UVM sources, and `sources.f` at the submission root. Features describe what must be verified; the test plan explains the legal preparation and stimulus, independent expectations, valid sampling, and checks that detect failure. JSON must carry all facts; Markdown must describe the same IDs, references, interfaces, behavior, and methods and cannot supply facts omitted from JSON. The two formats need semantic agreement, not identical wording. Use the fields, types, reference rules, and unrelated paired examples in `public/submission_format.md`. Reasonable splitting and merging are permitted; names and item counts do not substitute for correct content.

`flow/features.json` contains a nonempty `features` array with `feature_id`, `requirement_ids`, `module`, `definition`, `interface`, `timing`, and `boundary`; optional `parent_id` may be null or reference a defined feature without cycles. `flow/testplan.json` contains a nonempty `tests` array with `test_id`, `feature_ids`, `requirement_ids`, `stimulus`, `expected`, `checker`, `implementation_id`, and `source`. Required text fields are nonempty strings; reference and interface arrays are nonempty and contain unique strings. Use unique IDs, the public specification's R-IDs, the candidate's own feature references, and actual submitted HDL locations. State preparation history, the actual stimulus domain, the expected relationship and timing, and the independent comparison and failure condition in the existing fields. Keep complete facts in both JSON documents and preserve agreement with their Markdown counterparts.

Use UVM 1.2 with top `dvbench_top` and test `dvbench_test`. Provide real sequences, driver, monitor, agent/environment, predictor, scoreboard, checker, and functional coverage. Connect independent predictions from the submitted model to actual/expected scoreboard comparisons; protocol checks and coverage do not replace those comparisons. Report failures through `UVM_ERROR` or `UVM_FATAL`. After stimulus and checks finish, in-flight work drains, objections are released, and ERROR/FATAL counts are zero, emit `DVBench_COMPLETED` exactly once in the report phase.

Interact only through the native ports described in `public/ports.md`. `clock` accepts inputs, host accesses, and dequeues on falling edges; data outputs update after rising edges. `reset` is asynchronous active-high. Preserve the resolved bidirectional `hdata[7:0]` bus, `haddr[15:0]`, and descending 8-bit data vectors. The model must use a separately resolved bus receiving the same external host drive; do not connect its expected bus to DUT actual. Preserve the public host idle-gap and sampling windows. Preserve all port names, directions, widths, packed and unpacked index directions, and the contracted parameter profile. Do not submit a DUT implementation or stub, use internal hierarchical access, `force`/`release`/`bind`, DPI/VPI, file/system probes, network bypasses, or parameter overrides outside the public contract. `sources.f` must list submission-relative `.sv`/`.v` paths in dependency order and include `model/model.sv` and every real UVM source. It must contain no compiler options, absolute paths, parent traversal, or wildcards. Except for tool-provided `uvm_macros.svh`, includes must use safe paths within the submission. Public logical state names do not authorize internal hierarchy access.

## Mandatory Independent Model Entry Point

Define a self-contained SystemVerilog module named `dvbench_model` in `model/model.sv`, matching the native interface's port names, directions, widths, indexing, and parameters. The file must work independently without UVM, includes, or other submission files. Use this same file for independent model evaluation and in the testbench to produce expected values for the scoreboard; keep DUT actual outputs separate and compare actual against expected. Derive predictions only from reset, input stimulus, and their history. Do not instantiate the DUT, copy its implementation, read DUT actual to generate expectations, or replay golden outputs. A class, package, or function alone does not satisfy this module entry point.

There is no whole-task wall-time or cumulative token limit. Compilation, simulation, and individual model requests have separate limits; read `public/deployment_budget.json`.
