# dv-091-shared-mem: Build a Complete UVM Verification Environment

Read `public/spec.md`, `public/ports.md`, `public/submission_format.md`, `submission_contract.json` and `public/debug_feedback.md`. The DUT top is `shared_mem`. There are no top parameters: the fixed instance has four 32-bit lanes, two banks of 128 words, 3-bit instruction IDs and a four-slot response queue. `clk` is the rising-edge clock and `rst_n` is asynchronous active-low reset. There are no inout ports. Preserve descending packed indices and the least-significant lane-zero convention in `public/ports.md`. The RTL implementation is hidden; build your verification from the public behavior and native interface contracts.

Submit `flow/features.md`, `flow/features.json`, `flow/testplan.md`, `flow/testplan.json`, self-contained `model/model.sv`, all HDL needed for a complete UVM environment, and `sources.f`. Features explain what behavior is verified; the testplan explains how legal stimulus reaches the stated conditions, how expected results are predicted, when outputs are sampled, and how failures are detected. Follow the field types and references in `public/submission_format.md`: the JSON roots contain nonempty `features` and `tests` arrays, respectively. Feature entries carry `feature_id`, `requirement_ids`, `module`, `definition`, `interface`, `timing` and `boundary`; plan entries carry `test_id`, `feature_ids`, `requirement_ids`, `stimulus`, `expected`, `checker`, `implementation_id` and `source`. Use unique IDs, public requirement references, native interface names and real implementation locations as specified by the format. Use the same IDs and references in each Markdown/JSON pair, and put the complete facts in JSON; Markdown cannot fill JSON omissions. The two representations must agree semantically. You choose reasonable feature and test groupings.

Use UVM 1.2 with top `dvbench_top` and test `dvbench_test`. Connect independent expected predictions to actual/expected scoreboard comparisons in the complete environment. End finite stimulus, drain intended in-flight transactions, and release objections. Report failures with `UVM_ERROR`/`UVM_FATAL`. Print `DVBench_COMPLETED` exactly once in report phase only when both error and fatal counts are zero. The completion marker does not replace meaningful checks.

Instantiate the native DUT directly once in `dvbench_top` and interact only through its public ports. Submit ordinary files within the published snapshot limits. Do not redefine the DUT or use hidden hierarchy, `bind`, `force`/`release`, DPI, arbitrary dumps, file/OS/network system tasks, escaped identifiers or macro token concatenation. Standard UVM macros and ordinary empty header guards are permitted. `sources.f` must list one submission-relative `.sv`/`.v` file per line in compilation order and include `model/model.sv`; do not list DUT copies, compiler options, absolute paths, parent traversal or wildcards. Includes resolve relative to the submission root; includes other than the provided `uvm_macros.svh` must name files inside the submission. Do not choose compiler flags, simulator options, seeds or design variants.

## Mandatory Independent Model Entry Point

`model/model.sv` must define the self-contained SystemVerilog module `dvbench_model`. It must compile independently of UVM and all other submission sources. Match every native port name, direction, width and descending packed range in `public/ports.md`, including the clock and asynchronous active-low reset; there are no parameters to override. Derive expected outputs from inputs, reset and their history, independently of DUT actual outputs. Do not instantiate the DUT in the model or use DUT actual outputs as predictions. Use this identical file both for independent model evaluation and for prediction in the testbench scoreboard, with DUT actual and model expected outputs wired separately. Classes, packages or functions alone do not satisfy the module entry point.

You have at most **300 cumulative agent decision turns**, with a delivery reminder at turn **250**. The budget persists across compaction and recovery of the same run. There is no whole-task wall-time or cumulative token limit. Compilation, simulation, and individual model requests have separate limits; read `public/deployment_budget.json`.

Read failed feedback and its listed compiler logs, simulation logs, and public-interface waveforms. Repair the submission and rerun while budget remains. Save the complete submission and report its actual verification status. Do not use subagents.
