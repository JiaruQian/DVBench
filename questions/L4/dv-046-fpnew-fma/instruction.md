# dv-046-fpnew-fma: Build a Complete UVM Verification Environment

Read `public/spec.md`, `public/ports.md`, `public/submission_format.md`, and `submission_contract.json`, together with `public/debug_feedback.md`. The DUT top is `fpnew_fma`. Implement the three published FP32 profiles: default_logic (FpFormat=0, NumPipeRegs=0, PipeConfig=0, TagType=logic, AuxType=logic), original_comb (FpFormat=0, NumPipeRegs=0, PipeConfig=0, TagType=logic[3:0], AuxType=logic[1:0]), and original_pipe2 (FpFormat=0, NumPipeRegs=2, PipeConfig=3, TagType=logic[3:0], AuxType=logic[1:0]). Unlisted parameter combinations are outside this version's domain. The RTL implementation is hidden.

Submit `flow/features.md`, `flow/features.json`, `flow/testplan.md`, `flow/testplan.json`, a self-contained `model/model.sv`, complete UVM source code, and `sources.f` at the submission root. Features explain what to verify; the test plan explains legal preparation and stimulus, independent expected behavior, valid sampling, and how checks detect failure. Each Markdown/JSON pair must use matching IDs, references, and semantics. JSON must contain the complete facts; Markdown cannot supply facts omitted from JSON. Follow the field types, reference rules, and unrelated paired examples in `public/submission_format.md`. Feature and test grouping may be chosen by the candidate. Test-plan `implementation_id` and `source` must locate real checks in the submitted HDL.

Use UVM 1.2 with top `dvbench_top` and test `dvbench_test`. Supply executable stimulus, native-port driving and monitoring, independent prediction, scoreboard comparison, checks, and functional coverage. Connect the submitted model to the scoreboard and compare its expected values with observed DUT actual values. Report failures with `UVM_ERROR` or `UVM_FATAL`. After stimulus and checking finish, drain in-flight work, release objections, and confirm zero ERROR/FATAL before printing `DVBench_COMPLETED` once in the report phase. Completion and coverage do not replace valid checking.

Interact with the DUT through its native ports. Preserve the published names, directions, widths, packed/unpacked index directions, and parameter profiles. Retain clock clk_i and active-low asynchronous register reset rst_ni; the zero-stage profiles have no resettable pipeline state. Preserve operands_i as packed [2:0][31:0]. For default_logic, tag and aux are one bit and reg_ena_i is [0:0]; original_comb uses tag [3:0], aux [1:0], and reg_ena_i [0:0]; original_pipe2 uses tag [3:0], aux [1:0], and reg_ena_i [1:0]. There are no inout ports. List one relative `.sv` or `.v` path per line in `sources.f`, in dependency order, including `model/model.sv` and the complete UVM sources. Do not use absolute paths, `..`, wildcards, compilation options, or a DUT copy in the filelist. Includes other than tool-provided `uvm_macros.svh` must resolve within the submission using safe relative paths. Do not access DUT internal hierarchy, use force/release/bind or DPI/VPI, probe files/systems/networks for hidden assets, bypass the feedback interface, change parameters outside the published profiles, or submit a DUT implementation or empty stub.

Place each profile's complete UVM sources and filelist in `profiles/<profile>/` and share the root `model/model.sv`. Each profile filelist includes `model/model.sv`; the assembler materializes this same file into that profile's working root. Root `sources.f` remains the complete entry point for default_logic. Follow the profile layout in `public/submission_format.md`.

## Mandatory Independent Model Entry Point

`model/model.sv` must define the SystemVerilog module `dvbench_model` with the native DUT port names, directions, bit widths, index directions, and the published parameter profile. It must compile by itself without UVM, includes, or other submitted files. Use this identical file for independent model evaluation and for the predictor connected to the UVM scoreboard. A class, package, or function alone does not satisfy the module contract. Generate expected outputs only from reset, inputs, and their history; do not instantiate the DUT, copy its implementation, or derive predictions from DUT actual outputs. Keep actual and expected signals separate for comparison.
