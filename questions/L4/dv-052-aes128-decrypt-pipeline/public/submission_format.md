# Submission Format

A submits sources.f, flow/features.md and features.json, flow/testplan.md and testplan.json, model/model.sv, and the complete UVM implementation under tb/.
sources.f must contain one relative .sv/.v path per line, with no options or wildcards, and must include model/model.sv. The top level is dvbench_top and the test is dvbench_test. The model is a self-contained dvbench_model module, with ports, directions, and widths identical to ports.md, and no DUT instance, actual reads, or external files. The TB must instantiate the same model for independent prediction and have real sequence/driver/monitor/env/scoreboard/checker/coverage components. Output DVBench_COMPLETED once after legal completion, zero ERROR/FATAL, all transactions drained, and a nonzero comparison count.

The root of features.json is an object, and features is a nonempty array of objects. Each item's feature_id/module/definition/timing/boundary must be nonempty strings, and interface and requirement_ids must be nonempty arrays of unique strings; parent_id must be null or a defined feature_id, with no cycles. interface lists only the native ports actually relevant to this local item. The root tests in testplan.json is a nonempty array of objects; each item's test_id/stimulus/expected/checker must be nonempty strings, and feature_ids and requirement_ids must be nonempty arrays of unique strings referencing real IDs. Preparation, actual drive domains, independent expectations, valid sampling, and a checker capable of failing should be explicitly written into these fields. source may list actual implementation locations.

JSON carries the complete facts, and MD organizes synonymous descriptions by item; MD must not be used to supplement facts missing from JSON. Contradictions under the same conditions count as one local error. Names, counts, and grouping do not determine the semantic score. B submits only the two feature files; C submits only the two plan files, with the provided feature files read-only; D submits only the model; E submits the TB/filelist and uses the provided plan/model. The debugging feedback contract consists of compilation diagnostics, simulation logs, and public-port waveforms; access to the hidden implementation is prohibited.
