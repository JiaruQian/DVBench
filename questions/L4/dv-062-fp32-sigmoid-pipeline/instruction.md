# dv-062-fp32-sigmoid-pipeline: Build a Complete UVM Verification Environment

Read `public/spec.md`, `public/ports.md`, `public/submission_format.md`, and `submission_contract.json`, plus `public/debug_feedback.md`. The native DUT top is `fp32_sigmoid_pipeline`. The FTZ parameter defaults to 0; both FTZ=0 and FTZ=1 must be covered. The public contract permits two configurations within one dvbench_top, each connected to a parameterized model from the same model/model.sv and compared; sources.f contains the complete test. Preserve data_i and result_o as [31:0]. clk_i is the rising-edge clock; rst_i and clear_i synchronously flush valid markers when high. RTL is hidden. Preserve the exact native port names, directions, widths, packed and unpacked index directions, and parameter profile described in the interface contract.

Submit `flow/features.md`, `flow/features.json`, `flow/testplan.md`, `flow/testplan.json`, self-contained `model/model.sv`, complete UVM source code, and `sources.f`. Features describe what must be verified; the testplan explains the legal preparation and stimulus, independent expected behavior, valid sampling, and failure checks. JSON must contain all facts; Markdown must present the same IDs, references, and meaning and cannot supply facts missing from JSON. Follow the field types, references, and unrelated paired examples in the submission format. Reasonable feature and test grouping is allowed; names and entry counts do not establish correctness.

The feature JSON root is an object with a nonempty `features` array. Each entry has nonempty strings `feature_id`, `module`, `definition`, `timing`, and `boundary`, and nonempty arrays of distinct strings `requirement_ids` and `interface`. Use unique feature IDs, public R-ID references, and native port names. Optional `parent_id` references an existing feature or is null, without cycles. The plan JSON root is an object with a nonempty `tests` array. Each entry has nonempty strings `test_id`, `stimulus`, `expected`, `checker`, `implementation_id`, and `source`, and nonempty arrays of distinct strings `feature_ids` and `requirement_ids`. Use unique test IDs and valid references to your features and public requirements; `source` and `implementation_id` locate real submitted checks. State preparation, actual stimulus domain, expected relationships, sampling, and mismatch reporting concretely in the existing fields. Contradictory Markdown/JSON facts under the same conditions and window are errors for the affected obligations.

Use UVM 1.2 with top `dvbench_top` and test `dvbench_test`. Implement the stimulus, driver, monitor, environment, independent predictor, scoreboard, checks, and coverage needed for the complete environment. Connect the independent expected values and DUT observations to actual/expected scoreboard comparisons. Report failures with `UVM_ERROR` or `UVM_FATAL`. After legal stimulus and checking finish, in-flight observations drain, objections are released, and ERROR/FATAL counts are zero, emit `DVBench_COMPLETED` exactly once in the report phase. Completion and coverage do not replace effective checking.

Interact with the DUT through its native ports. Do not access internal hierarchy, use force/release or DPI, submit a DUT copy, or probe hidden files, the network, or the operating system. `sources.f` must list one submission-relative `.sv` or `.v` path per line in dependency order and include `model/model.sv`; it must contain no compiler options, absolute paths, parent traversal, or wildcards. Except for tool-provided `uvm_macros.svh`, includes must use safe relative paths within the submission. Preserve the clock, reset, bidirectional-net, and indexing rules in the native interface contract.

## Mandatory Independent Model Entry Point

`model/model.sv` must define the self-contained SystemVerilog module `dvbench_model` with the DUT's native ports and contracted parameter profile, including the exact directions, widths, and index directions. Use this identical file for independent model execution and prediction in the UVM scoreboard. It must work without UVM or other submitted source files or includes. Predict only from reset, stimulus and its history. Do not instantiate the DUT, copy its implementation, use DUT actual outputs as the expected result, or replay hidden expected outputs. Wire expected outputs separately from actual observations. Classes, packages, functions, protocol checks, or a disconnected model alone do not satisfy the module and scoreboard contract.
