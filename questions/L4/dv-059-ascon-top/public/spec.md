# ASCON native top-level behavioral contract

The top level for this task is ascon_top, which processes a caller-supplied five-word initial state, key, and data; it includes initialization, associated data, a plaintext-block loop, and finalization. There are no parameters, ready, or backpressure. It does not generate an IV, padding, or block partitioning, or verify tags on its own; the initial state may be any 320-bit binary value, and key/data may be any binary values of their respective bit widths. This specifies the complete observable top-level behavior.

## R-bba53466-001 Reset, start, and sampling

Rising edges of clock_i advance computation; resetb_i is active-low and asynchronously returns to idle and clears the logical round number and block count to zero. When computation is enabled, state clearing by reset is overwritten by the computation write in the same event; the state is guaranteed to be zero only when the enable is off during idle or waiting. Reset does not clear defined end_o, cipher_valid_o, or the external-state selection history. start_i=1 starts only when idle; start_i is ignored when busy; state_i, key_i, and data_i are not latched in their entirety at start, but use current port values in the computation windows described below.

## R-bba53466-002 Permutation mathematics and initialization

The state consists of five 64-bit words, with state_i[0] being the most significant packed word. Initialization executes rounds 0 through 11; after the last round, the upper 64 bits of key_i are XORed into word 3 and the lower 64 bits into word 4; the first round uses state_i at computation time, and subsequent rounds use the preceding mathematical state. Each round consists of constant injection, a 5-bit S-box, and per-word rotate-right XOR operations; see below for the complete mathematical definition and start timing.

## R-bba53466-003 Associated data

After initialization, wait for data_valid_i=1, then enter the associated-data window. This window XORs current data_i into word 0 and executes rounds 6 through 11; the last round only inverts the least significant bit of word 4 for domain separation, without XORing the key. The mathematical state is held while waiting, and data_valid_i outside waiting windows does not start a new block.

## R-bba53466-004 Plaintext, valid window, and wait count

After associated data, enter plaintext waiting with the block count at 0. Every rising edge in plaintext waiting increments the 2-bit block count by one, wrapping modulo 4, including the edge that accepts data_valid_i. During the one cycle after acceptance in which cipher_valid_o is 1, cipher_o is current mathematical state word 0 xor current data_i; rounds 6 through 11 are then executed, and cipher_valid_o returns to 0. Finalization waiting is entered only if the block count equals 3 when the last round completes; otherwise, return to plaintext waiting. The number of waiting cycles affects exit, so a fixed total of 3 plaintext blocks cannot be assumed.

## R-bba53466-005 Finalization and tag

Finalization waiting enters the first finalization round only after data_valid_i=1; the first round XORs data_i into word 0 and the upper and lower halves of key_i into words 1 and 2, while cipher_valid_o is 1 and cipher_o is word 0 xor data_i. Rounds 0 through 11 are then executed; valid is 0 starting with the second round, and the last round XORs the current upper and lower halves of key_i into words 3 and 4. On completion, end_o is set to 1 and tag_o is {mathematical state word 3,mathematical state word 4}; the next cycle returns to idle.

## R-bba53466-006 Holding, subsequent sessions, and undefined boundaries

end_o is undefined before the first completion and remains 1 after completion; neither subsequent starts nor reset clear it. cipher_valid_o is undefined before the first plaintext window; afterward, it is set to 1 only in plaintext or the first finalization round, cleared to 0 in the next round, and held during all other stages. After end_o=1, tag_o continuously reflects current mathematical state words 3 and 4, so it may change during a new session; it does not permanently latch the first tag. A numerical value is required for cipher_o only when predicted cipher_valid_o=1, and for tag_o only when predicted end_o=1 and the mathematical bits are defined. The round number during idle may reach 12 through 15; out-of-range constants and mathematical bits not yet overwritten by new initialization are undefined. No particular X pattern is required, and masks must not be determined from actual values.

### Computation timing and data usage

The following fixed timing example applies to a flow that begins with reset low at power-up, has no intervening reset, and whose previous operation ended normally. Denote the rising edge that accepts start as E0. E1 is the preparation cycle, E2 commits initialization round 0, and E3 through E13 commit rounds 1 through 11; after E13, wait for associated data. Current state_i between E1 and E2 is used for initialization; using only the value at E0 is not allowed. The preparation stage may produce a temporary state, whose valid outputs are handled according to the domain defined by R-bba53466-006.

During associated-data waiting, denote the edge accepting valid as A0; after A0, enter the first associated-data round window, using current data_i after A0 and before A1. A1 commits round 6, A6 commits round 11 and domain separation, then plaintext waiting follows. After plaintext acceptance edge M0, cipher_valid is set to 1, and cipher combinationally reflects current data during the M0-to-M1 window; M1 commits round 6 and clears valid, and M6 commits round 11, after which the number of waiting cycles determines whether to return to plaintext waiting or enter finalization waiting. The count includes M0 and every preceding waiting rising edge; the last associated-data round clears it to 0, and it is frozen during computation. After finalization acceptance edge F0, cipher is valid; F1 commits round 0 and clears valid, F12 commits round 11 and sets end, and F13 returns to idle. Continuously asserted start starts an operation on the next rising edge after returning to idle. Changes to data_valid during computation do not change progress; changes to data/key in the computation windows where they are actually used change the mathematical result.

Within the same time event, first compute the current round using the inputs and mathematical state of the preceding stage, then advance the stage. On asynchronous reset, if the preceding stage was preparation, initialization, associated-data, plaintext, or finalization computation, enabled computation writes take priority over clearing; the state is cleared on subsequent idle clock edges while reset is held low. reset clears the stage, logical round number, and block count, but data selection and defined flags are retained; round 0 of a new initialization reestablishes a determinate mathematical state from the external initial state. start is not accepted while reset is held low. Outputs are observed only after combinational settling; delta transients are not constrained.

### Permutation mathematics

All words are 64 bits, and bitwise XOR, AND, and NOT are limited to 64 bits; ROTR denotes 64-bit rotate right. For round number r=0..11, zero-extend the 8-bit constant ((15-r)<<4)|r and XOR it into word 2. Then apply the S-box in parallel to the 64 bit columns: form a 5-bit integer from the same bit of the five words, with word 0 as the most significant bit. The outputs for inputs 0..31 are, in order, hexadecimal
04,0b,1f,14,1a,15,09,02,1b,05,08,12,1d,03,06,1c,1e,13,07,0e,00,0d,11,18,10,0c,01,19,16,0a,0f,17。
After splitting the S-box output back into five words, update each word x to x xor ROTR(x,a) xor ROTR(x,b); the (a,b) pairs for words 0..4 are respectively (19,28), (61,39), (1,6), (10,17), and (7,41). The data/key pre-XOR required by a stage occurs before the constant, and the last-round key/domain-separation XOR occurs after the linear layer. 12..15 are not valid mathematical round numbers; no determinate value is guaranteed for temporary out-of-range results.


### Supplementary rules for reset and reentry history

To clarify observable behavior after an abort, input history may be used to maintain round number r and two retained reload settings p6/p12. Power-up reset sets r=0, and it does not increment before a start; after one start, every non-reset rising edge first updates r according to the preceding settings: if p6 is 1, load 6; otherwise, if p12 is 1, load 0; otherwise, increment by one modulo 16. reset clears r to 0 but does not clear p6/p12 or the history that counting has begun. When start is accepted, set p12=1 and retain the other settings; at the end of preparation, p12=0; on entering associated-data or plaintext waiting, p6=1, and after accepting that type of data, p6=0; on entering finalization waiting, p12=1, and after accepting finalization data, p12=0. If both are 1, p6 has priority. These settings are retained at all other times, including reset. Therefore, restarting after an intervening reset does not necessarily follow the fixed 13-cycle initialization example above; historical reloads must be carried forward. For example, p6 remaining 1 can keep initialization at round 6 indefinitely, and eventual completion cannot be assumed.

The initialization preparation cycle also commits a temporary mathematical update for the current round number, using the previously retained external-initial-state selection history; only in the first round-0 window does selection switch to current external state_i, and afterward it switches to the computed state. This selection is also retained during subsequent reset. Temporary round numbers 12 through 15 produce an undefined temporary mathematical image until the external initial state overwrites it; its specific unknown-bit pattern need not be predicted. During stage execution, each rising edge performs the mathematical operation using the round number before updating it, then updates the round number. Waiting stages hold the mathematical state. All flags before their first definition and undefined temporary mathematical images follow R-bba53466-006; defined results in complete initialization, associated data, plaintext, and finalization must still be verified at full bit width.
